# Case study 02  -  Payroll/HR vendor comparison without a forced winner

**Scenario:** Hypothetical 120-employee construction contractor. Required: five or more payroll states, mobile time for field employees, benefits, onboarding, integration with **QuickBooks Enterprise Desktop**, and possible rollout in six months. Compare candidate cost, implementation, support, reporting, field usability and scalability.

**Compilation:** `contract.xml` is copied without changing its bytes from the supplied original `PAYROLL.xml`. It encodes the non-negotiable conditions, conditional recommendation/no-winner outcomes, source anchors and evidence gates.

**Provided output:** `result.md` is copied from `PAYROLL PLATFORM Results.md`, dated October 20, 2026. It records **INSUFFICIENT_EVIDENCE**, not one selected vendor, because precise Enterprise compatibility and other qualification conditions are not confirmed. It treats QuickBooks Online and Enterprise Desktop as separate interfaces and requires supplier-specific proof.

**Professional signal:** A useful AI system must sometimes refuse to choose a winner when hard requirements are not verified. Explicit status is more defensible than a plausible-looking unsupported recommendation.

**Verification scope:** Runner 1.0.0 locally returned preflight PASS for the standalone XML, with warnings that the original Compiler release receipt/source events were not independently replayed. The referenced vendor information is a historical case report, **not** a current procurement assessment. No complete replay receipt of the historical research execution was supplied.
